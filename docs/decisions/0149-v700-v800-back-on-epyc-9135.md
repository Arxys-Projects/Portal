# 0149 - V700 and V800 go back on the AMD EPYC 9135 at 325 streams

- **Status**: Accepted (applied 2026-10-15)
- **Date**: 2026-10-15

## Context

On 2026-09-14 the V700 and V800 lost the AMD EPYC 9135 because it was reported EOL.
Migration `20260914000001` moved them to the V400's 8C/16T EPYC 9015. The same day,
`20260914000002` moved them to the V500/V600 part instead (`AMD EPYC 9005 3.3Ghz 16/32
Core`). Both migrations dropped their rating from 325 to 275 camera streams, so V500
through V800 became one CPU tier at one ceiling.

Andy has reversed that for the V700 and V800: they ship on the 9135 again (16C/32T, 4.3 GHz)
and are rated 325 streams. The V400 stays on the 9015 at 150, and V500/V600 stay on the
3.3 GHz part at 275.

A verbatim restore of the pre-September rows was possible, since the 2026-09-14 rollback file
captured them. Three of those values were questionable. The V800 turbo of 4.55 Ghz came from
an admin edit on 2026-07-27 and is not an AMD figure. AMD lists the 9135 at 3.65 GHz base,
4.25 GHz all-core boost and 4.3 GHz max boost. The old label also named the series
(`AMD EPYC 9005 ...`), not the part.

## Options considered

- **Run the 2026-09-14 rollback file.** Restores exact old values, but it also reverts the
  V400, and it brings back the V800's 4.55.
- **Restore the old V700/V800 values verbatim.** Keeps 4.55 on the V800 and the series-only
  label.
- **Restore with three corrections (chosen).** Same CPU and ceiling, with the part named,
  turbo 4.25 on both families, and base kept at the published 4.3.
- **Use AMD's exact figures (base 3.65).** More accurate on `/comparison`'s "Base Clock"
  row, but it departs from the 4.3 GHz Arxys publishes.

## Decision

All six V700/V800 `product_specs` rows get: `cpu_model_full` `AMD EPYC 9135 4.3Ghz 16/32
Core`, `cpu_base_ghz` 4.3, `cpu_turbo_ghz` `4.25 Ghz`, `cpu_passmark` 56984, and
`max_cameras` = `max_cameras_h265` = 325. Unchanged: `cpu_model` (`AMD EPYC 9005 Series`),
both cores/threads columns (16C/32T), `cpu_cache` (64MB).

The write goes through `scripts/revert-v700-v800-9135-cpu.ts`, which runs on the guarded
engine. Andy runs `--apply`. This is the same ADR 0096 exception as the October fixes:
audit rows carry `updated_by = null`.

## Consequences

**Positive:** the Price Book pages, datasheets, `/comparison`, `/videox-compare`, the
recommender, System Estimate PDFs and new Project Quotes all follow the data, so no product
code changes. V700 and V800 now agree with each other on every CPU column.

**Negative:** sizing changes again. V700/V800 take 325 cameras per box, so camera-dense,
storage-light jobs above 275 VSR can size onto fewer V700/V800 units than they did after
2026-09-14. Sales should hear this before the next quote. Existing quotes are frozen
snapshots and keep 275 / 3.3 GHz. `cpu_base_ghz` 4.3 is AMD's max boost, not its base
clock, and `/comparison` labels the field "Base Clock Speed". The V500/V600 label still
names the series while the V400, V700 and V800 name the part.

**When to revisit:** if the 9135 supply problem that prompted the September change comes
back, or if the base-clock figure on `/comparison` is questioned.
